Core Paradigm Shift

Procedural vs. Object-Oriented Code

Why do ML frameworks like PyTorch and Scikit-Learn rely 100% on OOP?

Legacy Procedural Separate State & Logic

Variables floating disconnected from functions

Functions take data as arguments, modify it, and return new data. If you have 50 students, you manage 50 separate variables manually.

# Data is scattered
student1_name = "Rahul"
student1_marks = 85

# Functions need variables passed manually
def calculate_grade(marks):
  return "A" if marks >= 80 else "B"
⚠️ Hard to scale, state leakage, repetitive argument passing.
Modern OOP Encapsulated Entity

Data + Actions bundled in one Object

Every student is a self-contained unit that knows its own name, marks, and can calculate its own grade automatically.

class Student:
  def __init__(self, name, marks):
    self.name = name
    self.marks = marks

  def get_grade(self):
    return "A" if self.marks >= 80 else "B"
✓ Modular, reusable, matches real-world entities (and AI models).

Object Birth Lifecycle

How the __init__ Constructor Works

What actually happens behind the scenes when you type s1 = Student("Rahul", 21)?

Step 1: Allocation

Memory Allocation

Python calls __new__ under the hood to carve out a new empty memory address block on the heap.

Address: 0x7fa281b490
State: {empty object}
Step 2: Self Binding

self is Passed

Python triggers __init__ and passes that new memory address as the first parameter: self.

def __init__(self, name, age):
  # self = 0x7fa281b490
Step 3: State Stored

Attributes Attached

Writing self.name = name binds the values into that object's private memory namespace dictionary.

s1.__dict__ = {
  'name': 'Rahul',
  'age': 21
}
💡 Trainer Pro-Tip for Students: __init__ never returns a value! It always returns None. Its sole job is to populate the instance.
The Core Mystery

Demystifying the self Keyword

Why do students forget it, and how does Python translate it behind the scenes?

1. It is the Explicit Instance Reference

In Java or C++, this is hidden behind the scenes. In Python, "explicit is better than implicit". self is explicitly passed so methods know which object they are modifying.

2. Method Call Syntactic Sugar

When you write student1.get_name(), Python automatically rewrites it to:
Student.get_name(student1).

3. What if you forget self?

Writing name = name inside __init__ creates a local variable that is destroyed as soon as the function exits!

Python Method Logic
class BankAccount:
  def __init__(self, holder, bal):
    self.holder = holder
    self.balance = bal

  def deposit(self, amount):
    self.balance += amount

  def withdraw(self, amount):
    if amount <= self.balance:
      self.balance -= amount
